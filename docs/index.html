A tiny app for macOS, Linux and Windows that plays your stations without a window, a browser tab, or a Dock icon. It comes with the best radio already built in — FIP Reggae — and takes any stream URL you add.

Small app, fussy about the right things

Everything it does is one menu click away, and it keeps playing when the stream misbehaves.

Menu bar or tray only

One status item. A waveform while it plays, circling arrows while it reconnects, and nothing in your Dock — the same on every platform.

Shows what is playing

The current track appears under the station name, read from the stream itself or from a feed the station publishes. Feeds are found automatically, so a station you add is covered without configuring anything.

Plays with your media keys

The station and track go to the system's own controls — Now Playing, MPRIS or SMTC — so Control Center, the keyboard keys and AirPods can pause and resume.

HLS and direct streams

Plays .m3u8 HLS streams and plain Icecast MP3 or AAC URLs, straight from the menu.

Playlist links welcome

Paste an .m3u or .pls URL and it fetches the playlist, finds the stream inside and plays that.

Reconnects on its own

Dropped or stalled streams are rebuilt with exponential backoff — 1s up to 30s — and a watchdog catches silence that never reports an error.

Handles sleep and wake

On macOS, waking rejoins the live stream instead of trusting a connection that froze overnight. Paused stays paused. The Rust build has the same backoff and watchdog; wake has not been tried there.

Remembers your volume

Set the slider once and it is still there next launch, at 100% out of the box.

Build it

Three small builds, no installer on any of them: a SwiftPM project on macOS, cargo on Linux and Windows. Each one ends the same way — an icon in the menu bar or the tray.

macOS

SwiftPM, macOS 14 or later, Xcode Command Line Tools — the Xcode app is not needed.

# builds build/Radio.app and launches it
git clone https://github.com/Jostein/Radio.git
cd Radio
make run

Linux

Rust, ffmpeg, GTK 3 and libayatana-appindicator; xdotool on Arch, because the tray library links libxdo.

# Debian / Ubuntu
sudo apt install build-essential libgtk-3-dev libayatana-appindicator3-dev \
  libasound2-dev libxdo-dev pkg-config ffmpeg

cd Platforms
cargo run -p radio --release

Windows

Rust and ffmpeg from winget, plus the MSVC build tools that rustup offers to install.

# PowerShell
winget install Rustlang.Rustup
winget install Gyan.FFmpeg
cd Platforms
cargo run -p radio --release

The macOS bundle is ad-hoc signed for local use: it runs on your Mac, but it is not notarized. The Linux and Windows binaries are plain cargo builds, with no installer on either.

One radio, three desktops

macOS is where it started. Linux and Windows run the same idea as one shared Rust build: the same stations file, the same tray menu, the same reconnect, the same media keys. All three are the app — the only difference is how much of each has been proven.

macOS

The original. Menu bar item, Now Playing and media keys, sleep and wake, playlists, volume. Built from this source and used every day.

Linux

Rust build. Tray icon and menu, playback with live titles, pause, volume, quit and MPRIS all seen on sway with waybar. In a VM with PipeWire it plays audibly — three seconds from the sink monitor at −14.4 dB.

Windows

Same Rust source. Compiles, links and passes the core tests on a real Windows runner, and the hidden window SMTC binds to is created. The tray and media flyout have never been started.

Same everywhere

The stations file and its starter station, an add dialog that suggests the station's own name, ICY and feed titles, reconnect with backoff, volume that persists, one stream at a time.

Deliberately different

The add dialog is GTK on Linux and a small Win32 window on Windows rather than an AppKit alert; volume steps instead of a slider, because tray menus have nowhere for one; and the track line is a 60-character budget rather than a measured width.

Media keys, all three

Now Playing, MPRIS and SMTC — the desktop's own media widget shows the station and track, and its buttons pause and resume the radio.

Where the evidence stops

All three platforms are the app; what differs is how much of each has actually been run. macOS is in daily use. Linux has been driven end to end in a container and a VM, on a virtual sound card. Windows has been built and tested but never started. If the tray is missing on your desktop, the menu opens in the wrong place, or the media flyout stays empty, that is the known limit of the evidence — the kind of thing that gets fixed in one sitting, not a mystery.

It is also fixable without waiting for anyone: the port is a small, plain Rust codebase whose README lists the parts that were never exercised. Open the repository with an AI coding agent, run it, paste what you see, and ask it to fix that one thing.
